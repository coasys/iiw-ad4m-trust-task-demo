1 Who are you in this demo?

The flow needs two people to accept a request. Either two people use one AD4M node, or each brings their own. Pick your part.

Using the other person's node over the network is not part of this demo. Their node would have to accept connections from the network, with passwords sent unencrypted.

Get the executor

The AD4M executor is the program that runs your node. It holds your keys, stores your data as signed links, and runs flows. It is one file. The page needs to know where it is.

Become a person on this node

One AD4M node can hold several people (multi-user mode). Each gets their own DID and keys and signs their own votes. The page adds you, makes a random password for you, keeps it on this computer and logs you in.

2 Start the node

Your node is the executor running with its own data folder (.node/). The page starts it the way start-node.sh does. The first start creates the folder and a random admin credential: whoever has that file controls the node. This page's server reads it and never shows it.

Watch the AD4M logo in the node panel: grey while the node is stopped, blue once it answers. Its log is at the bottom of that panel.

What came back

3 The node's agent, and people on it

An AD4M agent is a key pair and a did:key. Everything the agent writes is signed with that key. A new node has no agent yet: you create one and protect it with a passphrase. After every restart the agent is locked, and you unlock it with the same passphrase.

A second person on this node

With multi-user mode on, one node holds several people, each with their own DID and keys and a login. Adding a person turns multi-user mode on (see the People card in the node panel). The page makes a random throwaway password for each and keeps it in .demo/people.json.

4 Connect this page to your agent

An ordinary app never gets your keys or the admin credential. It asks the node for a capability: the right to act as your agent. The node shows the person at the node a one-time 6-digit code, and they type it into the app. Only then does the app get a token. That way a web page can ask, but only the person at the node can say yes.

This demo is a special case. Its server started your node, so it holds the admin credential. A bare executor approves the request by itself and writes the code to its log (that is what AD4M_LOG_SECRETS=1 does); the page reads the log and shows you the line. The calls are the same ones any app makes. In the ADAM launcher the code shows up in a window instead.

  1. The app asks
  2. The node writes a code to its log
  3. You type the code here
  4. The app has a token
What came back

5 Make a space

A space (AD4M calls it a perspective) is a graph of signed links. The trust tasks, the flow and the votes all go in it. A local space stays on this node. A neighbourhood is a shared space: other nodes join it by its URL, and AD4M syncs the links between them.

Local space

Only this node. Needs no network. Two people on this node can vote in it: a person added in step 3 owns it, and the node's agent is in it too.

Shared space

Make the space and publish it as a neighbourhood, so a second node can join. A link language moves the links between nodes. Pick one:

Connect first (step 4) to list them.

Join the shared space

The person who started the demo sends you a neighbourhood://… address. Paste it here. The flow comes in with the space's links; that takes a few seconds with the link server.

What came back

6 A trust task arrives

A requester sends a signed trust task to this demo app: "give Carol the role member". The app checks it with ToIP's code. If it passes, the app stores it in your space and AD4M starts a run of the flow, a small state machine. Two votes accept the request. One vote rejects it.

7 Vote

  
Each received task has its own run of the flow. Every person in the space votes with their own key; AD4M signs each vote as a link. Nobody sets the state directly: each node works it out from the signed votes it holds.

8 The receipt, the answer, and the requester's check

  
When a run has ended, this demo app asks AD4M to make a flow receipt: the signed votes, the final state and the exact request the group decided on. Its address is the SHA-256 of its content, so nobody can change it unnoticed. This demo app wraps it into a trust-task answer signed with its own key, and the requester checks the answer against the request it sent.
